== Testing

=== Backend unit tests

Backend tests are Kotlin tests under `server/src/test/kotlin`.
The project uses Kotest for test execution and assertions, with MockK and SpringMockK available for test doubles.
Follow the style of nearby tests and prefer testing observable behavior rather than implementation details.

Run the backend test suite from the repository root:

[source,shell]
----
./gradlew :server:test
----

To run one test class, use Gradle's test filter:

[source,shell]
----
./gradlew :server:test --tests 'de.ingrid.igeserver.exports.ingrid.LuceneModelTest'
----

For exporter tests, use the existing export test fixtures and helpers where suitable. `server/src/test/kotlin/de/ingrid/igeserver/exports/ingrid/GeodatasetBase.kt` provides shared setup for InGrid exporter tests, and `LuceneModelTest.kt` demonstrates assertions on the serialized Lucene JSON model.
Test both expected fields and important omissions; for index JSON, validate output against the schema as well.

Run the backend style check with:

[source,shell]
----
./gradlew :server:ktlintCheck
----

=== Backend integration tests

Integration tests can load Spring components and use a real PostgreSQL database through Testcontainers.
Extend the shared `IntegrationTest` base to inherit its Spring test configuration, active profiles, SQL fixture, and PostgreSQL container.
The container requires a working Docker environment.
Keep tests that need a full application context separate from fast unit tests.

Run integration tests with the same `:server:test` task; use a test-class filter to narrow the run while developing.
Add or reuse SQL and other fixtures under `server/src/test/resources` rather than depending on a developer's local database.

=== Frontend tests

Frontend specs use the Angular CLI test builder, Vitest, and jsdom.
Component and service specs are generally colocated with the implementation and use the `.spec.ts` suffix.
Spectator is available for creating component and service test contexts; see `frontend/src/app/+catalog/catalog.service.spec.ts` for an example.

Run tests from `frontend/` through the Angular CLI (do not invoke `vitest` directly, because the Angular builder configures the test environment):

[source,shell]
----
yarn ng test
----

For a CI-style non-watch run, the package script is:

[source,shell]
----
yarn test-ci
----

When changing Angular templates, run the frontend build as well: tests do not type-check every template.
